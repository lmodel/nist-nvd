# Datasets

* [NVD LinkML schema](nist-nvd-linkml-schema.md) - The LinkML schema of the NVD API 2.0's JSON responses, under `src/nist_nvd/schema/`: the umbrella `nist_nvd` over the modules `nvd_core`, `nvd_cve`, `nvd_cpe`, `nvd_cpematch` and `nvd_history`, and the vendored `cve_cvss`. It keeps NVD's keys, so a real response validates unchanged.
* [Vendored CVSS module](cvss-module.md) - lmodel/cve's `cve_cvss` module, copied unchanged to `src/nist_nvd/schema/cve/` and held to its git object hash by `tests/test_cve_import.py`, which also walks NVD's own CVSS files against it. Its classes are `CvssV20`, `CvssV30`, `CvssV31` and `CvssV40`.
* [Generated artefacts](generated-artefacts.md) - What the generators write from the schema, and which is never edited by hand: `project/`, `src/nist_nvd/datamodel/` and `docs/schema/nist_nvd.yaml`, under the settings in `.linkml/generators.yaml`.
* [The adapt copy](adapt-copy.md) - `.lokf/nist-nvd.yaml`, the copy `just lokf-adapt` writes from the schema with `--root NvdCve --prefix cve`, so it can sit beside LOKF's schema. It is the bundle's domain schema, and a release attaches it as `schema-<tag>-nist-nvd.yaml`.
* [Copies of NIST's JSON schemas](upstream-copies.md) - `upstream/`, the JSON schemas of the NVD API 2.0 as NIST publishes them, each pinned by SHA-256 in the watch. All are copied unchanged but the SSVC schema, of which only the structure is held.
* [Example data](example-data.md) - The examples the tests hold the schema to, under `tests/data/`: valid examples, counter-examples that each name the JSON pointer they fail at, a folder for valid data LinkML's example runner cannot take, and a committed extract of real NVD responses.
* [Extract of real NVD responses](nvd-extract.md) - `tests/data/nvd/`, real answers of the NVD API read on 2026-11-03 and unchanged: one record for each case worth showing, and samples of the product, match-string and change-history responses.
* [Neighbours' adapt copies](neighbour-copies.md) - `tests/neighbours/`, the adapt copies of other lmodel schemas, each pinned by SHA-256 in `tests/test_schema_rules.py`: slsa, github-actions, in-toto, oscal, spdx, stix, uco, cve and kev-catalog.
* [Mapping terms read at their sources](vocabulary-terms.md) - `tests/vocabulary-terms.txt`, the IRI of every term outside lmodel that the schema's mappings name, each read at its source on 2026-11-03: Dublin Core, schema.org, DCAT, PROV-O, SPDX 3.0.1, the SEPSES vocabularies and Wikidata.
* [The record for CVE-2023-29357](worked-record-cve-2023-29357.md) - NVD's record for CVE-2023-29357, a Microsoft SharePoint Server flaw in the KEV catalog, as a worked example of a concept typed `NvdCve`. Its keys come from `tests/data/nvd/cve-CVE-2023-29357.json`, cut down to the ones it needs.
